# Brainstorming

Use this before the design is stable.

1. Restate the outcome in one sentence a user would recognize.
2. List three approaches, including the boring one. Note the cost of each at the PRD's target scale.
3. Pick one. Write the reason and the approach you rejected so a later session does not revive it without new evidence.
4. Identify the smallest demonstration that would prove the approach: one API call, one state transition, one query plan.
5. Only then write the plan that names files and tests.

Stay in notes and sketches. Brainstorming does not include drive-by edits.
